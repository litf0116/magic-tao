## 测试规范文档模板

每个测试文档遵循统一格式：

### 1. 文档头部
```markdown
# {业务功能}测试规范

## 1. 测试概述
- 测试目标
- 测试范围
- 测试环境

## 2. 测试数据
- 测试用户
- 测试参数
- 测试配置
```

### 2. 测试用例
```markdown
## 3. 测试用例

### 3.{N} {用例名称}

**测试目标**: 验证XXX功能

**前置条件**: 
- 条件1
- 条件2

**测试步骤**:
1. 步骤1
2. 步骤2

**API 调用**:
\`\`\`bash
API 示例
\`\`\`

**验证点**:
- 验证点1
- 验证点2

**预期结果**: XXXXX
```

### 3. 测试验证
```markdown
## 4. 验证清单

- [ ] 功能验证项1
- [ ] 数据验证项2
- [ ] 异常处理项3
```

## 快速开始

### 1. 选择测试文档
根据需要测试的功能，选择对应的测试规范文档。

### 2. AI Agent 执行
将测试文档提供给 AI Agent，Agent 会：
1. 解析测试规范
2. 检查前置条件
3. 执行测试步骤
4. 验证测试结果
5. 生成测试报告

### 3. 查看测试报告
测试完成后，AI Agent 会生成标准化测试报告。

## 最佳实践

### 1. 文档编写原则
- 清晰性：步骤描述清楚，无歧义
- 完整性：包含所有必要信息
- 可执行性：AI Agent 可以理解和执行
- 可验证性：每个步骤都有明确的验证点

### 2. 测试数据管理
- 使用固定的测试用户
- 测试完成后清理数据
- 避免污染生产数据

### 3. 环境隔离
- 开发环境和测试环境分离
- 使用独立的数据库
- 配置独立的应用参数

## 常见问题

3. 验证测试数据正确性
