# Git Hook 已更新 - 仅使用 OpenCode 审查

## ✅ 修改内容

已将 Git Hook 修改为**只使用 OpenCode** 进行代码审查，移除了 Codex 审查。

## 🎯 修改原因

1. **超时问题**: Codex 启动 MCP 服务和模型加载需要时间，容易超时
2. **成本优势**: OpenCode 使用阿里云 GLM-5 模型，成本更低
3. **本地化**: 阿里云模型无需翻墙，速度更快
4. **简洁高效**: 单一工具，避免双重审查的复杂性

## 📊 审查流程

```
git commit
    ↓
检测代码文件 (.cs/.ts/.vue/.dart)
    ↓
OpenCode 快速审查 (阿里云 GLM-5)
    ↓
发现问题？ 
    ↓ Yes
提示用户是否继续
    ↓
完成提交
```

## 🚀 使用方式

### 正常提交（自动审查）

```bash
git add .
git commit -m "feat: 新功能"
# 自动运行 OpenCode 审查
```

### 跳过审查（紧急情况）

```bash
git commit --no-verify -m "emergency fix"
```

### 手动审查

```bash
# 使用脚本
./scripts/review-with-opencode.sh <文件路径>

# 或直接使用命令
opencode run -m alibaba-coding-plan-cn/glm-5 \
  "审查代码: <文件路径>"
```

## 💡 审查要点

OpenCode 会审查以下内容：

1. **代码质量** (40%)
   - 命名规范
   - 代码复杂度
   - 重复代码

2. **安全性** (30%)
   - 输入验证
   - 潜在漏洞
   - 敏感信息

3. **性能** (30%)
   - 算法效率
   - 资源使用
   - 潜在瓶颈

## 🔧 自定义审查

如果需要更详细的审查，可以手动调用：

```bash
# 深度审查
opencode run -m alibaba-coding-plan-cn/glm-5 \
  "请深入审查 <文件> 的架构设计、扩展性和安全性"

# 使用其他模型
opencode run -m deepseek/deepseek-chat \
  "审查 <文件> 的性能问题"
```

## ⚠️ 注意事项

1. **首次运行**: OpenCode 首次调用可能需要初始化，稍等片刻
2. **网络连接**: 确保可以访问阿里云 API
3. **超时处理**: 如果审查时间过长，可以选择跳过或稍后手动审查
4. **审查结果**: AI 建议仅供参考，请结合实际情况判断

## 📈 后续优化

如果审查过程仍有超时，可以考虑：

1. **增加超时时间**: 修改 Git Hook 中的审查提示词，要求更简洁的回答
2. **异步审查**: 提交后再进行审查，而非阻塞提交流程
3. **选择性审查**: 只审查关键文件，跳过文档和配置文件
