#### 2.1.2 业务流程

```
用户打开小程序
    ├──> 检查是否有登录状态
    │   ├──> 有登录状态 → 进入首页
    │   └──> 无登录状态 → 跳转登录页
    │
    登录页:
    ├──> 微信登录:
    │   ├──> 调用 uni.login() 获取 code
    │   ├──> 调用 weixinMiniAuthenticate 接口
    │   ├──> 获取 accessToken 和 openid
    │   └──> 存储登录状态 → 跳转首页
    │
    ├──> 手机号登录:
    │   ├──> 调用 uni.login() 获取 code
    │   ├──> 获取手机号授权
    │   ├──> 调用 phoneAuth 接口
    │   └──> 存储登录状态 → 跳转首页
    │
    └──> 账号密码登录:
        ├──> 输入账号密码
        ├──> 调用 authenticate 接口
        └──> 存储登录状态 → 跳转首页
```

#### 2.2.2 业务流程

```
拍卖流程:

1. 拍卖品上架
    └──> 进入拍卖品列表 (状态: "草稿" / "上架" / "拍卖中")

2. 拍卖开始
    ├──> 管理员调用 startAuction 接口
    ├──> WebSocket 广播拍卖开始消息
    └──> 订阅用户收到通知 (小程序订阅消息)

3. 拍卖进行中
    ├──> 用户进入拍卖聊天室
    ├──> WebSocket 实时连接
    ├──> 查看拍卖品详情
    ├──> 用户出价:
    │   ├──> 输入出价金额
    │   ├──> 校验出价规则 (最低加价、卡秒模式)
    │   ├──> 调用 bid 接口
    │   └──> WebSocket 广播出价消息
    ├──> 聊天室实时消息:
    │   ├──> 出价消息
    │   ├──> 卡秒状态变更
    │   ├──> 系统消息
    │   └──> 用户消息
    └──> 拍卖师操作:
        ├──> 开启/关闭卡秒模式
        └──> 结束拍卖

4. 拍卖结束
    ├──> 管理员调用 endAuction 接口
    ├──> 确定中拍用户
    ├──> WebSocket 广播成交消息
    └──> 为中拍用户创建私聊频道

5. 拍卖成交
    ├──> 中拍用户收到成交消息
    ├──> 创建拍卖师与中拍用户的私聊
    ├──> 拍卖师联系中拍用户
    └──> 完成交易
```

#### 2.3.2 业务流程

```
WebSocket 连接流程:

1. 预连接
    └──> 调用 ws.preConnect() 获取 WebSocket 服务器地址和 ID

2. 建立 WebSocket 连接
    ├──> 调用 wx.connectSocket() 连接服务器
    ├──> 监听 onOpen → 连接成功
    ├──> 监听 onMessage → 接收消息
    ├──> 监听 onError → 连接错误,5秒后重连
    └──> 监听 onClose → 连接断开,5秒后重连

3. 消息类型处理
    ├──> Text: 文本消息
    ├──> Image: 图片消息
    ├──> Receipt: 回执消息
    ├──> Welcome: 欢迎消息
    ├──> Goodbye: 告别消息
    ├──> BanUser: 封禁用户
    ├──> Backout: 撤回消息
    ├──> AuctionStart: 拍卖开始
    ├──> AuctionBid: 出价消息
    ├──> AuctionEnd: 拍卖结束
    ├──> AuctionDeal: 拍卖成交
    ├──> KasecStatusChanged: 卡秒状态变更
    └──> Error: 错误消息

4. 聊天功能
    ├──> 私聊:
    │   ├──> 选择联系人
    │   ├──> 进入私聊页面
    │   ├──> 获取历史消息
    │   ├──> 发送消息 (ws.sendMsg)
    │   └──> 实时接收消息
    │
    ├──> 群聊:
    │   ├──> 创建群组 (createChannel)
    │   ├──> 加入群组 (subChannel)
    │   ├──> 进入群聊页面
    │   ├──> 获取历史消息
    │   ├──> 发送消息 (ws.sendChannelMsg)
    │   ├──> 离开群组 (leaveChannel)
    │   └──> 解散群组 (delChannel)
    │
    └──> 拍卖聊天室:
        ├──> 进入拍卖聊天室
        ├──> 订阅拍卖频道
        ├──> 发送消息
        ├──> 接收实时消息
        └──> 查看出价消息
```

## 五、总结

### 5.1 核心发现

1. **功能复杂度**: 拍卖系统和聊天系统是核心功能,占总工时的 59.8%
2. **高风险点**: WebSocket、登录、支付、推送是需要重点关注的迁移点
3. **可复用性**: 业务逻辑和 UI 组件大部分可复用,主要替换平台 API
4. **技术栈优势**: Vue 3 + TypeScript + Pinia 的技术栈有利于迁移

### 5.2 迁移建议

1. **技术选型**: 推荐 UniApp App 模式,最大化代码复用
2. **分阶段迁移**: 按模块优先级逐步迁移,降低风险
3. **核心优先**: 优先实现用户认证 → 聊天系统 → 拍卖系统
4. **并行开发**: 可按模块并行开发,提高效率
